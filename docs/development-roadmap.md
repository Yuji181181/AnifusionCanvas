# AnifusionCanvas 開発ロードマップ

最終更新: 2026-05-18 JST

## 方針

当面のゴールは、「AI中割り」と「Inpainting」だけを本番環境で普通に使える状態にすること。

細かいテスト整備、CI拡張、手動編集、書き出し機能の改善は優先しない。手動編集と書き出しの既存コードや API は残すが、ユーザーが触るフロントエンド UI からは外す。

## 現在の公開スコープ

| 区分 | 扱い | 内容 |
|------|------|------|
| AI中割り | 継続開発 | 2枚の原画から ToonCrafter で中割りフレームを生成する |
| Inpainting | 継続開発 | 生成済みフレームを選び、マスクとプロンプトで部分修正する |
| タイムライン | 継続 | 生成・修正済みフレームを確認し、Inpainting 対象を選ぶ |
| 手動編集 | UI非表示 | 既存実装は残すが、サイドバーと通常導線から外す |
| 書き出し | UI非表示 | 既存実装は残すが、サイドバーと通常導線から外す |

## 実装済み

- Cloudflare Pages の React SPA と Cloud Run の Go API による本番構成
- Replicate 実推論モードでの ToonCrafter / SDXL Inpainting 呼び出し
- R2 公開 URL を使った Replicate 参照用画像保存
- TiDB のフレーム URL 長尺化マイグレーション
- AI中割りの開始、ジョブ進捗表示、タイムライン反映
- ToonCrafter の配列形式出力を動画 URL として扱う修正
- Inpainting の対象フレーム選択、マスク作成、修正ジョブ開始
- 失敗時の再試行パネル
- 手動編集 / 書き出し UI の非表示化と旧 URL の `/step1` リダイレクト

## 優先ロードマップ

### P0: 本番で普通に動く状態にする

- 本番環境で AI中割りを 1 回通し、生成結果がタイムラインへ反映されることを確認する
- 本番環境で Inpainting を 1 回通し、修正結果がタイムラインへ反映されることを確認する
- Replicate / R2 / TiDB / Cloud Run の設定不足があれば運用ドキュメントへ追記する
- 失敗メッセージを AI中割り / Inpainting の利用者が判断しやすい表現へ整理する

### P1: 使い勝手の最低限の改善

- 生成中・修正中の待ち時間表示をわかりやすくする
- Replicate の課金が発生する操作であることを必要十分に伝える
- 入力画像やマスクが不正な場合の案内を改善する
- 生成結果が空、または Replicate 出力形式が想定外だった場合の診断情報を残す

### P2: 運用安定化

- 本番デプロイ手順と環境変数チェックリストを最新化する
- 既存の最小検証だけを維持し、テストや CI の新規拡張は行わない
- API やバックエンド内に残る手動編集 / 書き出し関連コードは、今後必要になった時だけ再整理する

## やらないこと

- 手動編集 UI の改善
- 書き出し UI の改善
- 新しい動画書き出し機能の開発
- 細かい E2E 拡充や CI ワークフロー改善
- Testcontainers などのテスト基盤拡張
- shadcn/ui への全面移行
- ポートフォリオ動画や宣伝素材の作成

## 受け入れ基準

- サイドバーに表示される導線が「AI中割り」と「Inpainting」のみである
- `/step3`、`/step3/edit`、`/export` に直接アクセスしても通常導線へ戻れる
- AI中割りで生成されたフレームをタイムラインで確認できる
- タイムライン上のフレームを Inpainting 対象として修正できる
- README と運用手順が、現在の公開 UI スコープと矛盾していない
